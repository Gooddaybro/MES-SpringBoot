# R006 第一批：受控关联查询与工艺快照对比

## 已授权范围

按用户任务末段执行：先核实、制定文件级计划，再实施第一批并测试、记录；继续原 `agent` 分支，不另建项目或切换分支。本轮不增加聊天写入、确认令牌、批量状态提交或新的知识库。用户已明确要求本轮直接实施，不再增加设计审批轮次。

## 现状与选择

基线 `75f9b49` 已有 R005 四业务独立子图、Java 受控事实与 HMAC、工单冻结 JSON 快照、独立事务状态流转、Layui 工作台，默认测试 Java182/Python135/Node20 通过。

采用扩展现有服务和签名事实契约的方案，复用原路径；不改为 Python 直连数据库，也不建立带数据库访问权限的通用工具回调。数据库关联和差异属于确定性规则，由 Java 执行；LangGraph 按受控条件组织依赖步骤，不能宣称模型自主查询数据库。

## 查询与权限

- 独立搜索支持物料名称、真实 `is_deleted`（0正常/1删除/2禁用）、工序名称、物料关联工序/路线、工单状态与创建时间。
- 所有列表采用稳定排序、页码及页大小限制，额外取一行判断下一页，不将当前页条数当总量。LIKE 参数转义 `%`、`_`、`!`，查询均绑定参数。
- 工序关联查询先解析工序，零结果返回真实空；多个候选返回 `AMBIGUOUS` 并停止下游，要求提供完整编码。物料名称搜索同样保留所有候选，不自动选首条用于其他业务。
- 路线/物料关联使用 `flow_id`、`oper_id`；工单按创建时快照的 `operationId` 反查，不能拿当前路线代替历史路线。
- 独立查询检查对应 `mes:assistant:*:read`。跨四模块查询先检查四项权限再查询；对比先检查工单与路线权限。没有工厂/租户隔离字段，只能提供当前项目的角色能力控制，明确不宣称已实现行级隔离。

## 工艺对比

读取原 WorkOrderService 的历史快照和 MaterialRoutingService 的当前关联路线。当前表没有发布版本/生效日期，不称为“最新已发布标准”。按工序真实 ID 和顺序比较新增、删除、顺序、编码与名称变化；重复出现的同一工序按出现次数配对。缺失 ID、无效顺序或损坏结构返回 `SNAPSHOT_UNRELIABLE`，不补造旧数据。现有快照不保存工时、温度、扭矩及 `oper_type`，列为不可比较项。

输出工单编号、物料、状态、两组工序、差异、潜在影响及需工艺人员确认项。任何路径不写回快照或主数据。路线缺失、断链、物料被删除时明确返回不能完成当前标准对比。

## LangGraph 与界面

保留独立四业务分派；新增 `operation_chain` 模式，先运行工序子图并校验唯一 ID，再分派已签名、参数与该 ID 一致的下游事实。空/歧义/失败直接聚合，依赖事实不被执行。总期限覆盖前置节点，原签名、防重放和只读工具白名单保持。

自然语言只识别明确句式，如“查询包含老化测试工序的物料及相关工单”和“对比工单 WO-XXX 的工艺与当前工艺”。复杂或冲突条件要求显式补充，不能让模型猜条件。现有抽屉支持名称补充条件；工作台增加只读搜索、工序关联查询及差异表单，保留原创建和状态表单。所有响应继续以文本 DOM 展示。

## 数据与验收边界

3307/mes_study 当前为物料100112、电工胶带，路线/工序/工单为空；3308/mes_study 为既有独立学习库，有 SERVO-DEMO-* 和 WO-SERVO-DEMO-001，不是生产数据。两者分别记录，不能混作一个环境。本轮不接管3308 Flyway历史、不重放初始化脚本、不增加表/字段。

验证顺序：新增失败测试 → 最小实现 → 专项测试 → 全量回归 → 3308事务回滚集成测试及3307只读核验 → 文档与提交/推送。学习库数据指纹前后相同。真实生产端到端建单不在本轮验收范围，第二批依赖有效工艺及用户显式人工确认。
