# R003：Java 8 受控模型意图适配

日期：2026-10-27。分支 `agent`，起点 `781ed2d`。启动检查工作区干净、远端一致；继续现有工程，未升级框架、创建 Python 服务或实现多步工具循环。

## 已实现的调用链

`Shiro authc → Controller 登录与 mes:assistant:routing:read → 输入长度/安全规则 → 规则单编码直查，或单编码未解决问题请求 LlmIntentClient → Java 复核白名单和原文完整候选 → MaterialRoutingService 只读查询 → 数据库事实及识别元数据`。

GET 结构化查询、帮助、写入/SQL/明显注入、格式错误、缺少编码、多编码和已知不支持业务不调用模型。未知单编码问句才补位。用户无编码时要求明确工艺问题及编码，不接受模型补全。输入大小写、点、下划线、斜线、短横线逐字保留，不能用子串或大小写转换匹配。重复相同编码可以；两个不同编码要求澄清。数据库本身仍可能使用不区分大小写的 collation，但模型参数校验不因此放宽。

英文不做全局常用词过滤：`GO`、`IT`、`MAKE`、`for` 都可能是合法编码。只在完整匹配的 `show material routing for CODE`、`how is CODE made`、`which stages does CODE go through` 等语法中识别编码位置，该位置内的单词仍逐字保留。不完整的 `routing for` 要求补充；真实编码 `for` 可写 `show routing for for`。混合或不确定的多 token 表达保守澄清。

## 服务端配置

| 环境变量 | 规则 |
| --- | --- |
| MES_LLM_BASE_URL | 兼容 API 根路径，如 `https://api.openai.com/v1`；去尾斜线追加 `/chat/completions`，已含该后缀不重复 |
| MES_LLM_MODEL | 运维确认的实际模型 ID，不设虚构默认模型 |
| MES_LLM_API_KEY | 仅服务端 Authorization Bearer 头；不写配置仓库、前端或日志 |
| MES_LLM_CONNECT_TIMEOUT_MS | 可选，默认 3000，允许 1–60000 |
| MES_LLM_READ_TIMEOUT_MS | 可选，默认 15000，允许 1–60000 |

缺任一必需项返回 `MODEL_NOT_CONFIGURED`；非法 URL、头字段、超时或不安全的 JVM 全局 CookieHandler 返回 `MODEL_INVALID_CONFIGURATION`，不阻止规则路径和应用启动。只允许远程 HTTPS，HTTP 限字面回环地址；不允许 user-info/query/fragment，不跟随重定向。base URL 是部署者可信配置，不能由用户问题改变；供应商网关、TLS、DNS 和访问策略仍由部署环境管理。

在启动 Java 的 PowerShell 会话中设置前三项；Key 可通过 `Read-Host -AsSecureString`/凭据管理注入，不能在共享命令历史写真实值。设置后重启 Java 才会读取新值。`Start-Local.ps1 -Rebuild` 子进程继承本会话变量，不读取 Codex 或其他应用的账号凭据。变量未配置时仍可查询 `100112` 或 `SERVO-DEMO-CTRL-001`。

请求为非流式 Chat Completions，只有 model、stream=false、system/user messages；不依赖供应商特定 JSON schema 或工具调用功能。依据：[OpenAI 官方 Chat Completions](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create)。第三方兼容服务和具体模型仍需各自联调。

## 输出契约与状态

只接受 `choices` 中一个 assistant message、`finish_reason=stop` 和文本 content；拒绝工具调用/函数调用、拒绝内容和截断结果。内层必须是恰好四字段 JSON：intent、materialCode、clarificationNeeded、reason。禁止重复字段、尾随 JSON、代码围栏、额外 SQL 字段、类型强转。最大 HTTP 体 64 KiB、content 2048 字符、reason 256 字符、JSON 嵌套 16 层。

intent 仅 `QUERY_MATERIAL_ROUTING`、`UNSUPPORTED`。查询未要求澄清时必须有合法编码；要求澄清时允许 null，UNSUPPORTED 必须为 null。Java 在业务调用前再次检查编码格式和唯一原文候选。模型 reason 不用于生成业务答案，也不写日志。

| 路径 | recognitionSource | modelAttempted | modelConnected | fallbackReason |
| --- | --- | --- | --- | --- |
| 规则命中/安全拒绝/GET | RULE | false | false | null |
| 未配置且需补位 | RULE_FALLBACK | false | false | MODEL_NOT_CONFIGURED |
| 网络/HTTP/结构/原文校验失败 | RULE_FALLBACK | 实际是否发起 | false | 对应稳定原因码 |
| 成功并通过所有必要校验 | MODEL | true | true | null |

模型合规返回 UNSUPPORTED 或主动要求澄清也可为 MODEL；不会执行工具。模型识别通过后数据库出现 503/504 仍保留 MODEL/true/true，数据库状态独立呈现。`modelConnected=true` 仅代表本次调用与校验，不代表全面验证。

故障码包括 MODEL_TIMEOUT、MODEL_CONNECTION_ERROR、MODEL_HTTP_401、MODEL_HTTP_429、MODEL_HTTP_5XX、MODEL_HTTP_4XX、MODEL_HTTP_3XX、MODEL_INVALID_JSON、MODEL_UNKNOWN_INTENT、MODEL_INVALID_PARAMETERS、MODEL_RESPONSE_TOO_LARGE。降级只要求用户补充或改用明确规则查询，不自动重试、不把猜测编码交给数据库。

## 隐私与执行边界

外发内容仅本次原始问题与固定识别指令，不包含数据库工序/BOM/库存/工单结果、用户会话、账号密码或 API Key 提示文本。Key 只出现在必需的服务鉴权头。模型不接收工具查询结果，不生成 SQL，不返回工艺事实。问题本身可能包含敏感信息；抽屉已明确提示不要填写，部署者需确认供应商的数据处理约定。

请求日志只记录 traceId、接口、状态、识别来源、尝试标志、稳定失败码、耗时，不记录输入问题、模型 reason/响应或异常消息。专用 RestTemplate 绕过会记录请求体的消息转换器；部署不得启用 HTTP wire/header/body 跟踪。前端等待 150 秒，为最大可配置连接 60 秒、读取 60 秒及本地数据库等待留出余量；仍需核对反向代理及实际数据库等待。读取超时是 socket 空闲超时，并非整个请求的总时限；缓慢持续传输不受该总预算保证。
